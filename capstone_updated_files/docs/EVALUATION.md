# Evaluation

Reproduce: `python scripts/evaluate.py --seeds 30 --out /tmp/out.txt` (seeded, deterministic). Unit/integration
tests: `pytest` (87 tests).

## What the numbers say
**Anomaly detection (A).** Environments are generated by `analyzer/synthetic.py`: identical "team" stars
(users -> team role -> team bucket) plus four injected anomalies (a hub role bridging teams, a user with access
to every bucket, a 4-hop chain ending in admin, an admin role trusted by an external account). The task is to rank the
injected identities above the normal ones.

* **Node2Vec + LOF on embeddings alone is unreliable**: AUC 0.695 +/- 0.246 (vs 0.513 random). Variance is large, and a
  hyper-parameter sweep (dim 8-32, 30-150 walks, q 0.5-2.0) never exceeded 0.74 AUC. Embeddings of structurally identical
  identities differ by random-walk noise, which LOF reads as "outlier".
* **Simple structural features (degree, privilege, reach) + LOF are a strong baseline**: AUC 0.872 +/- 0.047.
* **Hybrid (balanced Node2Vec + structural features) scored best**: AUC 0.904 +/- 0.072, precision@k 0.643. But the paired
  improvement over the structural-only baseline is small (+0.031, 95% bootstrap CI +0.000 to +0.061, wins 67% of seeds),
  so **this benchmark does not show that Node2Vec clearly adds value over plain structural features**.
  The hybrid is the shipped default (`detect_anomalies(use_structural=True)`); the embedding-only mode remains available.
* Two bugs found while evaluating, both fixed: (1) LOF degenerates when more than `k` identities are identical, which is the
  normal case in IAM (`adaptive_k`); (2) an unbalanced hybrid (32 embedding dims vs 5 structural) lets embedding noise dominate
  (AUC 0.77) and a very small embedding weight breaks exact ties (AUC ~0.62-0.66), hence the variance-balanced blend.

**Consistency (B).** For every (principal, role) pair in 10 generated environments, the graph's assume-edge existence
agrees with the independent `check_trust_policy` in 5550/5550 cases. This is a *consistency* check on explicit,
same-account trust; it does not cover root-trust, cross-account, conditions or the permissions half of a path.

**Scaling (C).** Graph build, chain detection and path enumeration are cheap (< 1 s at 536 identities, hop limit 4).
Node2Vec dominates runtime (about 12 s at 536 identities). Path enumeration is bounded by `MAX_HOPS` but is exponential in
the worst case of very dense trust graphs.

## Limitations / threats to validity
* The anomaly benchmark is synthetic and the injected anomalies are defined structurally, i.e. in the same terms the detector
  sees. Treat the AUC as a sanity check, not as expected real-world accuracy. No labelled real IAM data was available.
* Offline verification evaluates identity/bucket/trust policies only. It ignores SCPs, permission boundaries, session
  policies, resource policies other than S3 bucket policies, KMS, VPC endpoints, and does not evaluate Condition values
  (statements with a Condition are reported `conditional` / `inconclusive`). It was **not** compared with the AWS IAM Policy
  Simulator because no AWS credentials were available in the build environment; use `--simulator` against the test account to
  cross-check.
* CloudTrail `LookupEvents` covers management events for the last 90 days only (no S3 data events). The live path was not run
  against a real account; parsing is tested on generated events in the standard CloudTrail record format.
* The classifier and risk scorer weights are heuristic and untuned on real data.
